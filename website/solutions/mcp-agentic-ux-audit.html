How the MCP Bridge Works

100% of synthux Features, Orchestrated by Your AI Agent

synthux-mcp bridges desktop MCP hosts with the Chrome extension's MV3 Service Worker over a hardened local WebSocket channel.

01 · End-to-End Browser Control

Open Tabs, Scan DOM & Render Live Overlays

Agents call open_and_audit_url, scan_page_ux_context, run_wcag_audit, toggle_heatmap, and capture_annotated_screenshot to inspect real authenticated browser sessions and localhost dev servers.

02 · Dual Evaluation Modes

Agent-Brain Mode or Extension AI Engine

Run audits using the extension's configured provider (Ollama / BYOK) via run_ux_audit, or use prepare_external_audit + submit_external_audit so your host agent (Gemini 4 Argon, Claude, Cursor) evaluates the page directly.

03 · Hardened Loopback Security

Origin Firewall, Token Pairing & Key Redaction

Bound strictly to 127.0.0.1:17483. Blocks all http:// and https:// web origins from cross-site WebSocket hijacking, supports SYNTHUX_MCP_TOKEN pairing, and never exposes stored API keys.

Quick Setup — Add to mcp_config.json (Antigravity, Claude Desktop, Cursor, Windsurf, Codex) npx -y synthux-mcp 
{
  "mcpServers": {
    "synthux": {
      "command": "npx",
      "args": ["-y", "synthux-mcp"]
    }
  }
}

MCP Architecture & Security FAQ

Frequently Asked Questions

Do I need a separate API key in the Chrome extension if I already use Antigravity, Claude, or Cursor?

No. Using the prepare_external_audit and submit_external_audit MCP tools, synthux extracts the live DOM, WCAG violations, and screenshot, and lets your host AI agent perform the evaluation using its own model brain.

Can a random website I visit connect to the local synthux-mcp server?

No. synthux-mcp enforces a strict Origin firewall that rejects any HTTP or WebSocket request carrying an http:// or https:// web origin, binds exclusively to 127.0.0.1, and supports an optional SYNTHUX_MCP_TOKEN shared secret.
